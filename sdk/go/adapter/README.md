# GRAMStack adapter Go SDK

Module: `github.com/theflywheel/GRAMStack/sdk/go/adapter` (Go 1.24+).

The SDK supplies registry-neutral resource projection, pinned mTLS service transport, strict JSON/canonical snapshot handling, registry-approved subject verification strict ES256 grants, a protected retrieval handler, and optional encrypted PostgreSQL context/attempt custody through `database/sql`. The host supplies the SQL driver, approved native verifier, resource and explicit profile version; the SDK imports neither gateway internals nor registry code. LokOS uses these SDK extension points rather than duplicating the protocol implementation.

`NewVerification` requires contract version `VerificationVersion` (0.1.0), registry, gateway certificate identity, approved verification method, resource, SubjectVerifier and ContextStore. Its HTTP handler serves POST `/internal/v1/subject-verifications`. Both request and response pin `Gramstack-Subject-Verification-Version`. See the [versioned wire contract](../../../specs/subject-verification/0.1.0/README.md).

Verification recomputes the accepted snapshot digest, enforces supported fields and request/authentication expiry, and calls the registry's verifier. A locator and login alone never create ownership. Live retries converge on the same context, bound to request, principal and a private issuer/subject digest. A different person cannot reuse that cached binding. The native verifier returns an opaque source-owned mapping handle, not business data.

`NewSQLContextStore` requires a host-managed PostgreSQL connection and stable random 32-byte key. `Migrate` is an explicit, serialized, checksummed operator action; startup never runs DDL. Mapping payloads and their private principal digest are AES-GCM encrypted with authenticated request/context/digest/principal/expiry metadata. SQL enforces TTL on every read. Fresh verification may replace an expired tuple; live contexts cannot be mutated. Physical cleanup and overlapping key rotation are separate operator responsibilities. No production keys or database credentials are provided by this package.

`ReadSelected` is a projection primitive, not an authorization boundary. The protected grant/redemption/evidence pipeline must admit a disclosure before calling it. The reference runtime enables the protected retrieval handler through explicit configuration; verification-only hosting remains available. SDK release/publication and external conformance are tracked separately in D13.

Use the root Go workspace for local SDK + LokOS development. Independent check scripts use temporary module files before release; no local replace is committed in module files. Published SDK tags use `sdk/go/adapter/vX.Y.Z`. From the repository root, run `./scripts/rehearse-sdk-release.sh HEAD` to build and race-test LokOS against a candidate version from a temporary Go module proxy, then exercise projection from a separate consumer module. The rehearsal uses committed source, disables the workspace, and leaves publication to the release step.


## Protected retrieval building blocks

`NewGrantVerifier` pins the issuer, exact adapter audience and copied P-256 public keys. It verifies compact ES256 `gramstack-grant+jwt` signatures, exact typed canonical claims, mandatory bindings and strict integer time bounds. Token-supplied key URLs, unknown fields/types, duplicate JSON, excess lifetime and ambiguous scope fail closed.

`NewRetrieval` requires the approved registry/method, provider, grant verifier, context store, attempt store, authority and evidence clients, evidence signing keys, explicit `batch` or `synchronous` release profile and concurrency limit (1–64). Its POST `/internal/v1/retrievals` handler requires verified gateway service mTLS and core 0.3.0. Presenter context is trusted only from that gateway after it has authenticated the original consumer certificate; forwarded identity headers are ignored. The SDK recomputes the snapshot digest, checks exact fields, consumer, purpose, deadlines and verified source mapping before claiming any attempt.

Processing order is durable local claim → new atomic reservation → durable source-start checkpoint → one provider call → exact projection → canonical salted response commitment → signed evidence → protected evidence checkpoint → durable custodian acknowledgement → release-start checkpoint → response write/final outcome. The concurrency slot stays held through response writing. Unknown source values and extra source fields never enter a response or evidence. The 32-byte random salt and signed evidence are recoverable from encrypted adapter custody; source plaintext is never persisted. A batch deployment can release at a durable `pending` acknowledgement; synchronous release requires `anchored`. An acknowledgement must identify the exact signed evidence bytes. The custodian must implement the durability promised by this interface; an in-memory acknowledgement is insufficient for a deployment.

`NewSQLAttemptStore` uses the host's PostgreSQL connection and stable 32-byte state key. Explicit `Migrate` installs checksummed schema version 2. `looplab/fsm` decides transitions and SQL row/version checks serialize them. Unique attempt, request and grant slots survive restarts. Even an identical duplicate returns 409 rather than cached business data or another fetch. A crash after a claim conservatively occupies the slot; there is no automatic retry of ambiguous authority/source calls. A failed/partial response write becomes DELIVERY_UNKNOWN. A lost final checkpoint remains RELEASE_ATTEMPTED, which is also never replayed. Recovery/anchoring workers and terminal-history reporting are separate host responsibilities.

Provider implementations must issue at most one native source request per `Fetch`, disable implicit transport retries that could repeat a read, and respect cancellation/timeouts. The SDK bounds provider invocations; it cannot infer hidden retries inside a custom provider. Hosts supply pinned mTLS clients, source/evidence secrets and release/retention policy. `NewAuthorityClient` supplies strict bounded private redemption/evidence RPCs without redirect following or application retries.

Configured reference-runtime acceptance now exercises the actual gateway → SDK → fictional native source → durable custodian → response path over mTLS, including exact projection, outages and restart. This does not claim a complete product UI, published SDK or verified automatic anchoring. Independently published SDK versions and external conformance remain D13.


## Public discovery

A configured `RetrievalService.DiscoveryHandler()` serves anonymous GET `/.well-known/gramstack-adapter` and `/.well-known/gramstack-adapter/jwks.json`, with discovery profile 0.1.0 and core 0.3.0 headers. It materializes only configured resource/method/capability metadata and public P-256 signing keys; a host must mount it on its public metadata listener separately from protected mTLS RPCs. It exposes no private parameters, source records, consumer tokens or authority URLs. Verification-only hosting cannot claim this full pipeline. Clients must compare every key point/ID and required resource/version with operator-approved trust; no fetched key becomes trusted automatically. The reference gateway does this before each SQL dispatch.

## Provider conformance

Import `github.com/theflywheel/GRAMStack/sdk/go/adapter/conformance` from an adapter test and call `CheckProvider` with a fictional, verified subject, one field and its expected JSON, and a counter on the fixture native source. The suite checks exact projection and one native read, and verifies that invalid scopes, missing mappings, and cancelled requests cause zero reads. LokOS runs it for both of its fields. These checks cover the provider boundary. Verification, grant redemption, evidence custody and HTTP transport require separate acceptance.
